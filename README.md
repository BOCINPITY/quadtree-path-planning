# QuadPath Lab

基于四叉树空间划分的路径规划可视化实验台。它做的事情不复杂：把一张栅格地图压缩成自适应空间，再看着 A* 和 Dijkstra 在这片空间里各走各的路。

在线体验：https://clesbit.top/lab/quadpath/

最早它是我的毕业设计。

选这个题，我看中的是它“有算法、有可视化、能讲清楚”：四叉树怎么切空间，A* 和 Dijkstra 怎么找路，再把过程一步步画出来。那时候我白天在实习，晚上下班回来接着做。累是真累，但也真是想把这件事做成。

## 技术原理

三个角色，各管一件事。

**四叉树**管的是“空间怎么表示”。普通栅格图每个格子都是一个节点，直白但浪费：一大片空地明明是一个整体，却被拆成几千个点。四叉树反过来，从整张图开始递归四分，区域状态一致就停，只有同时装着空地又装着障碍的区域才继续切。结果就是空旷处被几个大节点概括，障碍边缘依然保留细节。

**Dijkstra** 管的是“怎么保证最短”。它从起点出发，永远先扩展当前累计代价最小的节点，不猜终点方向。只要边权非负，它一定给你最短路径，代价是常常向四面八方铺开搜。

**A\*** 管的是“怎么更聪明地找同一条最短路径”。它在 Dijkstra 的已走代价 `g(n)` 上，加一个到终点的估计 `h(n)`，按 `f(n) = g(n) + h(n)` 决定先扩展谁。这里用的启发式是节点中心之间的几何距离。带着方向感，它通常更快逼近终点。

从实现上看，两者其实是同一套搜索，只是启发式不同：Dijkstra 就是 `h(n)` 恒为 0 的 A*。

一句话理清关系：四叉树不是第三种寻路算法，它负责把空间压小、组织好；Dijkstra 和 A* 负责在这片缩小后的空间里找路。

在 Lab 里，每次编辑地图都会重建四叉树，收集所有可通行叶节点；两个自由叶节点只要在空间上共享一条边界就连成一条边，权重取节点中心之间的几何距离。起终点映射到各自所在叶节点后，A* 和 Dijkstra 在**完全相同**的图上跑。所以对比是公平的：空间结构、起终点、边权都一样，变的只有扩展策略。

需要说明的是，这里的“最短”指的是**四叉树图上的最短**，不是几何意义上的最短。节点用叶节点中心代表、路径取中心连线，所以穿越大片空白叶节点时会先向该节点中心靠拢再离开——这是用单个点代表一整块区域换来的代价。

## 现在能做什么

- 在网格地图上绘制或擦除障碍物，自定义起点和终点
- 实时构建四叉树并显示叶节点边界
- 在大小不同的自由叶节点之间建立真实的共享边邻接关系
- 运行 A* 和 Dijkstra，对比路径长度、扩展节点数和耗时
- 回放搜索节点的扩展过程
- 导入 / 导出地图 JSON，内置可重复的测试场景
- 中英文界面、浅色 / 深色主题
- 用 Vitest 验证空间划分、邻接和四叉树图上的最短路径一致性

## 跑起来

```bash
npm install
npm run dev
```

检查测试和生产构建：

```bash
npm run check
```

所有计算都在浏览器本地完成，不需要后端服务。
